# 学习协作与开发流程

本文规定 Yog-Sothoth 作为学习驱动、研究导向渲染 Runtime 的默认协作方式。目标是让实现者形成原理理解和设计能力，而不是由 Agent 代替实现核心系统。

## 项目优先级

默认优先级为：

```text
理解原理
  > 形成设计能力
  > 完成可验证的纵向实现
  > 获得可测量的性能
  > 扩展功能覆盖
  > 对外提供稳定产品
```

“完整能力”表示一条窄范围但端到端闭环的渲染 Runtime，不表示复制商业引擎的功能数量。

## 协作责任

实现者负责：

- 在编码前说明自己的理解、假设和设计；
- 选择核心数据结构、状态机与所有权模型；
- 编写关键算法和主要实现；
- 对性能结果提出假设并解释最终代码为什么正确。

Agent 负责：

- 拆分纵向 slice 和学习依赖；
- 在编码前追问模糊的边界和不变量；
- 解释原理、候选方案和 trade-off；
- 设计或搭建公共契约测试；
- review 生命周期、并发、错误与性能问题；
- 协助分析编译错误、测试失败和测量结果；
- 维护规格、ADR、术语和实现的一致性。

除非实现者明确要求“直接实现”，Agent 不完成核心算法或架构实现。格式化、构建脚本、重复声明和简单脚手架等机械工作可以直接完成。

## 分级提示

实现者卡住时，默认按以下顺序提供帮助：

```text
第 1 级：指出需要重新思考的方向
第 2 级：解释相关原理和约束
第 3 级：给出伪代码或接口形状
第 4 级：给出局部代码示例
第 5 级：仅在明确要求后实现完整方案
```

## Slice 学习循环

每个纵向 slice 固定经历：

1. **原理准备**：明确问题、状态、不变量、所有权、并发、错误和性能风险；
2. **设计预测**：实现者先写目标、生命周期、接口和暂不处理的范围；
3. **契约红灯**：通过 Host 可观察 seam 建立一个失败测试；
4. **最小实现**：只实现使当前契约变绿所需的行为；
5. **Review 与反例**：检查是否碰巧通过，并增加最有价值的反例；
6. **性能实验**：在稳定路径上提出假设、测量、优化并比较前后结果；
7. **学习复盘**：记录预测、实际发现、设计变化和仍不理解的问题。

保持 `WIP = 1`：当前 slice 未完成 review 和复盘前，不同时开始另一个大型模块。

## 性能原则

性能分为两层：

- **架构性能不变量**：稳定帧无堆分配、无文件 I/O、无 shader/pipeline 创建，render 非阻塞，query 不推进，poll 有预算，CPU 不同步等待 GPU；
- **实验性能目标**：在固定硬件、驱动、分辨率、场景和 warm-up 下报告原始数据、p50、p95 和峰值资源。

先实现简单正确的 reference implementation，再依据 profiler 和计数器设计优化；没有数据时不进行性能重构。

## 依赖策略

Runtime 生命周期、Scene Snapshot、Workload、资源状态、同步、Validation 和诊断等学习主线由实现者设计和实现。Vulkan loader、窗口、shader 前端编译、图片编码和训练框架等外围能力优先使用成熟工具。

GPU allocator、任务系统、数学库和 reflection 等能力可以先使用成熟实现建立基线，只有在明确的学习 Epoch 中才替换窄范围组件。

## 论文准入

论文首先是实验假设，不直接成为核心产品功能。默认路径为：

```text
阅读笔记
→ 独立最小复现
→ 传统基线对照
→ 通过既有 Feature/Adapter seam 接入
→ 正确性与性能证据
→ 保留、重做或删除
```

论文特有类型不得泄漏进 Host C ABI 或 Runtime Core。一次只推进一个研究主题，复现失败或收益不成立也是有效结论。

## 结构演进

架构文档描述目标方向，代码目录只表达已经存在的真实边界。只有模块拥有独立状态与不变量、独立 seam、明确依赖、第二种 implementation 或独立生命周期时才提取，不提前创建未来模块空壳。
