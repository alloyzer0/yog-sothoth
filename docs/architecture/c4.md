## Level 1：System Context

```mermaid
C4Context
    title Yog-Sothoth System Context

    Person(developer, "渲染开发者/研究者", "实现 Feature、运行实验、分析证据")
    System(host, "宿主应用", "游戏、编辑器、仿真或自定义工具")
    System(yog, "Yog-Sothoth", "可嵌入、可验证的前沿实时渲染内核")
    System_Ext(authoring, "离线创作与训练工具", "生成场景、参考光照、模型和资产包")
    System_Ext(driver, "GPU 与驱动", "Vulkan 设备、队列、内存和执行能力")
    System_Ext(ci, "CI/实验系统", "Headless 回归、指标比较和产物归档")

    Rel(developer, yog, "配置 Feature 和实验")
    Rel(host, yog, "通过稳定 C ABI 提交场景和帧请求")
    Rel(authoring, yog, "提供版本化 Render Asset Package")
    Rel(yog, driver, "提交编译后的 GPU 工作负载", "Vulkan")
    Rel(ci, yog, "通过 Headless Host 运行与采集证据")
    Rel(yog, host, "返回 FrameTicket、Output 和诊断")
```

### 系统职责

Yog-Sothoth 负责渲染执行、资源生命周期、工作负载编译、能力选择与诊断。它不负责通用游戏逻辑、资产创作、神经模型训练或完整编辑器。

## 部署形态

Phase 1 只有单进程部署：Viewer 或 Experiment CLI 与 Runtime 位于同一进程。跨进程 Worker 是未来 Host Adapter，不进入首阶段。

Runtime 可以作为静态库或动态库构建，但二者必须暴露相同 C ABI。语言 SDK 只做类型安全和生命周期包装，不复制业务逻辑。
